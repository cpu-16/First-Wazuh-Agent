# Integración con n8n

## 7) Integración con n8n

El workflow trabajado en este laboratorio es:

```text
First_Wazuh_Agent
```

Actualmente combina funciones de consulta, triage y respuesta controlada.

**Arquitectura práctica:**

- varios nodos HTTP Tool para Indexer (9200) con Basic Auth
- 1 Code Tool para listar agentes via API Wazuh por proxy `55001`
- 1 Code Tool para Active Response via API Wazuh

**No conviene mezclar todo en un solo nodo porque:**
- cambian endpoints
- cambia el tipo de auth
- cambia la semantica (alertas, agentes, vulnerabilidades y acciones)

### 7.1 Nodo HTTP (Indexer 9200) — Body ejemplo (últimas 2h)

**Configuración:**

- **Method:** POST
- **URL:** `https://100.109.242.43:9200/wazuh-alerts-4.x-*/_search`
- **Auth:** Basic (`admin` + pass)
- **Header:** `Content-Type: application/json`

**Body:**

```json
{
  "size": 10,
  "sort": [{ "@timestamp": { "order": "desc" } }],
  "_source": ["@timestamp","agent.id","agent.name","rule.id","rule.level","rule.description"],
  "query": { "range": { "@timestamp": { "gte": "now-2h", "lt": "now" } } }
}
```

### 7.2 Tool de agentes (API Wazuh via proxy 55001)

En la version actual ya no se usa el flujo clasico de dos nodos `Authenticate -> List agents` dentro del agente de IA.

Se usa un `Code Tool` llamado:

```text
wazuh_list_agents
```

Este tool:

- autentica contra `https://wazuh.taild88ec5.ts.net:55001/security/user/authenticate?raw=true`
- hace `GET /agents?limit=200&select=id,name,status,lastKeepAlive,version,ip`
- devuelve un string TSV apto para herramientas AI de n8n

### 7.3 Tools analiticas sobre Indexer

Ademas del nodo de alertas basico, el workflow integra estas tools:

- `Top source IPs in alerts`
- `Top triggered rules`
- `Investigate IP in alerts`
- `Agent risk summary`
- `Vuln summary by agent`

Estas tools permiten responder preguntas como:

- que IPs te estan atacando mas
- que reglas o tecnicas aparecen con mayor frecuencia
- que agentes estan mas expuestos
- que evidencia existe para una IP concreta

### 7.4 Tool de respuesta controlada

La tool:

```text
Block IP via Wazuh active response
```

usa la API de Wazuh para enviar:

```http
PUT /active-response?agents_list=001,002
```

con un body tipo:

```json
{
  "command": "firewall-drop",
  "arguments": ["203.0.113.45"],
  "alert": {
    "data": {
      "srcip": "203.0.113.45",
      "reason": "SSH brute force"
    }
  }
}
```

La tool valida que:

- exista confirmacion explicita
- la IP no sea privada o interna
- el comando sea valido (`firewall-drop` o `netsh`)

> Recomendacion: usar esta accion junto con aprobacion humana, whitelist y auditoria.
